# System check and beta test, 24 October 2026

Run on a local copy (a throwaway database, the built app, a stand-in for Supabase login and storage), then read-only checks of the live database and site. Nothing here changed live data.

## What was run
- Typecheck, lint, migration drift check, embedded-migration freshness.
- Unit and integration tests: 540 pass (in-memory database), 544 pass (real Postgres).
- A fresh database built from the migrations alone, then the app built and started against it.
- The browser beta test (`bash e2e/run.sh`, see `e2e/README.md`): 130 steps in a real browser across seven scenarios: public pages; a Pakistani company and a US company signing up; an operator; a Pakistani company setting up vehicles, an employee, a photo, a job card and its policy (scanned PDF read by OCR, findings applied); staff, a fleet manager and a workshop joining by company code (approve, decline, replace the code, rate limit); paying with tax invoices, withholding, certificates, ledger and CSV; a trial running out; one company trying to reach another; script injection; phones, accessibility and speed.
- Supabase's own security and performance advisors on the live project.
- `scripts/audit-system.mts`: a read-only health check of the live database.

## Found and fixed
1. **Sign-up page crashed React on load (hydration error).** The country list was built separately by the server and the browser. Now built once on the server.
2. **Dropdown choices were lost after a failed save** (for example the country on the sign-up form). React does not re-apply a changed default to a select. Fixed in the shared select and four other forms.
3. **A workshop could open the company's Billing page** and see its price, plan and payment reference. Workshops now get "no access", and other non-administrators no longer see the payment reference.
4. **Three pages scrolled sideways on a phone** (dashboard, Users, Employees). Grid columns could not shrink below their content. One rule fixes all grids.
5. **A file field had no label for screen readers** on the job card form, and grey text failed the contrast minimum in several places. Fixed.
6. **The session cookie could be read by scripts on the page.** It is now HttpOnly, SameSite=Lax, and Secure over https. (No browser-side Supabase client exists, so nothing needs to read it.)
7. **The sign-in page had no way to start a trial or join a company.** Links added.
8. **A customer abroad was shown a rupee amount** in the payment instructions. Now only shown to customers in Pakistan or of unknown country.
9. **Invoices printed an empty "Sales tax reg." label and "NTN —"** when there was nothing to show. Tidied.
10. **Public API roles held table privileges** on a few older tables (row security kept them closed, so nothing was exposed). Control migration 0009 revokes them and closes the default for new tables. *Not yet applied to the live database.*
11. **A fresh install of migration 0009 failed on a database with no `postgres` role.** Found by the clean-install run; guarded.

## Open, for decisions
- The company owner (Administrator role) cannot approve job cards, and approving needs a workshop chosen in the same step. A new company needs a manager and a workshop before its first job can move. Options: give the Administrator the approval permission, allow approval without assignment, add a first-run checklist.
- Terms of service and privacy pages still have bracketed placeholders and a draft marker.
- The vendors page renders two copies of its Add form with the same field ids (one hidden by screen size). Invalid HTML, harmless to use.
- Leaked-password protection is off (needs the Supabase Pro plan). Free-plan email limits will block sign-up confirmations at any volume.
- Live settings still empty: bank details, seller sales tax registration, fallback exchange rate, support email, tax authorities. The forex.pk fetch is off until written consent is on record.
- 92 database functions in the tenant schemas have a changeable search path (advisor warning). They are not elevated-rights functions and rely on the per-request schema path by design; fixing means qualifying every name.
- 50 foreign keys have no covering index and 21 indexes are unused (advisor notes). Irrelevant at today's volume; revisit with real data.

## Not covered
- Supabase's own behaviour (real email delivery, storage row security, rate limits), because the browser test uses a stand-in.
- The live Netlify host running the OCR (tested from the packaged output on a laptop, not on the host).
- Payment by real bank transfer, real tax rates (none are entered), card payments (none exist).
- Load: no test with many companies at once beyond the existing concurrency tests.
