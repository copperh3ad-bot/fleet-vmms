# ADR-013: Design alignment, access audit, uploads and beta hosting

Status: accepted (owner instruction, 2026-10-22: "optimize app as per the design", "host it on netlify", "fix all gaps").

- **Tokens, not renamed classes.** The design's colours and type are applied by remapping the Tailwind shades the screens already used (`globals.css`, `@theme`), with IBM Plex through `next/font`. Shared pieces (`Plate`, `Pill`, `Kpi`, `PageHeader`, `Panel`, `btn`, `money`) live in `components/ui.tsx`; every screen uses them, so a design change is one edit.
- **Where the board and the rules disagree, the rules win.** The board's role table shows Finance without "edit budgets"; the database gives Finance `budget.manage`, so the screen shows what the database says (budgets and service rules are separate rows). The board's "Not used yet" and "last seen" for people are not shown: there is no per-person rule to base the first on, and last sign-in lives with the identity provider, not in our database.
- **Approving and assigning a workshop is one step** on the review screen. It is one transaction through the same transition function, so both events are written and the approver is still the signed-in user.
- **ADR-006 stands for the driver odometer link.** The phone page was restyled to the board but still shows only the plate and the month and takes a number. The board's owner name, last reading and dashboard photo are not shown: a link sent in a message must not reveal more than the plate, and a photo upload from an open page widens what an anonymous request can write. If the owner wants either, it needs a new decision.
- **Vehicle photo and registration scan** are attachments of a new kind, `vehicle` (tenant migration 0016: constraint and guard). The kind of file is the start of its stored name. Adding or removing needs `vehicle.write`; seeing needs `vehicle.read`, and a person limited to their own vehicle only sees that vehicle's files.
- **Access changes are audited.** Role, scope and status changes and invitations are in public tables, which the tenant audit does not reach. Platform migration 0007 adds an append-only `platform_audit_log` written by triggers on `tenant_memberships` and `invitations`. It records who (the signed-in user in `app.user_id`), what and when, never an invitation's token hash, and is not readable through Supabase's public API. Nothing in the app reads it yet.
- **Vehicle users are always limited to their own vehicle** (forced when invited or changed to the Requester role). Administrators can raise job cards for any vehicle (migration 0015); approval stays with fleet managers.
- **Uploads fit the host.** Netlify functions refuse a body over about 6 MB, so photos are shrunk in the browser (longest side 2200 px), the limit is 4 MB a file and 5 MB a request, and the server's own 4 MB check is unchanged. Files chosen on the new job card or accident form are attached after the record is saved; a file that cannot be stored never undoes the record, it is reported.
- **Hosting for the beta: Netlify, by hand.** Netlify's Next.js runtime builds the server (the standalone output used for containers is skipped there). Secrets are set as site variables from the developer's `.env.local` without printing them. Document reminders run as a Netlify scheduled function (03:00 UTC), which has no web address, so rule 5 is not widened. The database connection is the pooled one; each serverless copy keeps at most 3 connections.
- **Not built:** manager and weekly-summary alerts (no sending channel), "last seen" on people, photo and last reading on the odometer link, a screen that reads the platform audit log.
