# ADR-055: Joining with a company code is confirmed by a WhatsApp code and needs a valid licence

Status: accepted, 2026-11-07. Owner request: people joining with the company code must confirm by WhatsApp, to avoid fake joinings; must submit their licence number; onboarding needs a valid (not expired) licence; learner permits only if the company allows them, as an on/off setting for each company. Extends ADR-016 (joining with a code), ADR-044 (driving licences), ADR-054 (a licence at invite) and ADR-046 (the invitation code).

## Decision
1. **The form asks for more:** the person's WhatsApp number, the licence type (full licence, or learner's permit), the licence number and its expiry date. All are required.
2. **Confirmation by a code sent on WhatsApp.** The request is saved as `unconfirmed` and is **invisible to the administrator**. A 6-digit code is sent to the number they typed, from the Fleet OTG number, using the **approved authentication template the invitation code already uses** (`WHATSAPP_OTP_TEMPLATE`). The person is taken to the "request sent" page, which asks for the code; only when it is typed does the request become `pending`, the administrators get told, and it appears in the Users list marked "number confirmed on WhatsApp". Entering someone else's number is harmless: only the holder of that phone sees the code.
3. **How the page knows which request.** The browser holds a random reference in an httpOnly cookie (`join_ref`, scoped to `/join`, 3 days), routed in the control plane (`link_routes`, kind `joinconfirm`, control migration 0018); only its hash is stored. Someone on another device simply asks to join again. The code is made on the server, only a hash of it is stored (and neither hash enters the audit log), it works for **10 minutes**, **five wrong tries** end it, a new one may be asked for once a minute and at most five are sent for one request: the invitation code's limits. Every try also counts against the visitor's address and the reference.
4. **Why a code and not a link.** A link in a WhatsApp message would need its own template. Meta rejected both a Utility and a Marketing version of "confirm it was you" as the wrong category (it treats that as identity verification, which it allows only as an Authentication template, and those cannot carry a link). The code needs no new template and works at once. No new public page was added.
5. **Closed by design when WhatsApp is not set up.** Without the WhatsApp number, token and `WHATSAPP_OTP_TEMPLATE`, joining with a code is refused with "ask your administrator" rather than letting unconfirmed requests through. A code that cannot be sent removes the request again, so no licence number is left behind. Further limits: the existing per address and per email limits, plus **3 codes an hour to one number**, so the form cannot be used to message a stranger repeatedly.
6. **A valid licence.** A licence that has expired is refused, at the form and again at approval (it may lapse while the request waits). A **learner's permit** is accepted only if the company has set **"Accept learner driving licences"** to 1 in Settings (`allow_learner_licence`, tenant migration 0033; off by default, each company separately). The same rules apply to the invite form (ADR-054), which gains the same choice of licence type; the type is recorded on the licence (`driver_licences.licence_type`).
7. **Approval.** For a person joining as staff the licence is saved as the employee's (the employee record is made at approval if it does not exist yet, so the licence has somewhere to go) and the number is **removed from the request**. Declining removes it too. A request made before this change has no licence and cannot be approved: decline it and ask the person to ask again. A request nobody confirmed is deleted, with its licence number, a day after its three days ran out (the daily job).
8. **Audit.** The platform audit trigger drops both hashes and masks a licence number to its last four characters (platform migration 0015), so the append-only log never holds a number whole or anything a six-digit code could be worked back from.
9. **Not covered:** workshops (they do not join with a code, ADR-033), and people who are already members.

## Owner steps
Nothing new in Meta: the authentication template `fleetotg_code` is already approved and `WHATSAPP_OTP_TEMPLATE` is already set on production. Run platform migration 0015, control migration 0018 and tenant migration 0033 on live, then deploy. (Two templates for a link version were rejected by Meta and are not used.)
